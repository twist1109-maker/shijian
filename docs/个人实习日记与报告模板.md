模板、篇数、字数和最终提交日期以学校最新通知为准。不要把AI执行的开发工作写成本人独立手写完成，也不要编造考勤、运行日期或真实调用结果。

## 实习日记：每天复制一份
- 姓名 / 学号 / 班级：________
- 实际日期 / 地点 / 时长：________
- 当日目标：________
- 本人实际操作：例如资料核对、VS Code启动、配置模型、修改文案、运行测试、录制演示。只填写实际做过的操作。
- 可核查产出：文件名、任务ID、版本ID、提交记录或截图编号：________
- 遇到的问题及处理：错误现象 → 查找依据 → 修改或操作 → 复测结果：________
- AI辅助用途及本人验证：________
- 当日收获与下一步：________

可选主题按实际过程安排：需求理解；GitHub拉取与环境配置；教学资料整理；模型Key配置排错；工具调用观察；正文修改与审核；价格依据核对；版本比较；测试与回归；PPT与答辩演练。不能为了凑篇数虚构日期。

## 实习报告建议结构

### 1. 基本信息与摘要
填写实习单位、课程、时间、本人信息。摘要说明“图书营销资料转化为可审核图文”的业务目标、实际完成范围和验证结论。

### 2. 业务需求与项目目标
说明营销人员和审核人员的职责、输入资料、输出图文，以及为什么需要来源、版本和人工审核。对照任务书的必做功能，避免把选做功能说成全部必须。

### 3. 系统设计与技术实现
参考已交付设计说明与三张图，解释浏览器、Python、SQLite、模型接口和两类工具。强调模型选择工具，后端执行并检查权限；不提交密钥。

### 4. 本人承担的任务
如实写明本人负责的配置、资料、修改、验证、测试或展示。区分AI辅助完成的代码和文档、本人的修改与核对，以及尚未完成事项。可引用GitHub提交，但不要将AI提交一概认定为本人独立编码。

### 5. 测试与实际结果
分别报告自动化测试、目标机浏览器操作和真实模型调用。填写本人实际使用的服务商、模型、日期、任务ID、输出核对和缺陷处理。模拟响应、模拟故障、测试替身均明确标识；没有实际运行的内容写“未验证”。

### 6. 问题、改进与反思
可结合真实遇到的SSH认证、配置文件名、按钮状态、数据不足与文案事实核对等问题，说明如何定位及复验。记录仍存在的规则覆盖、网络和人工审核限制。

### 7. 结论与附件
根据真实结果评价目标达成程度；附件可列源码仓库、设计说明、PPT、测试记录、本人脱敏运行证据与录屏。参考来源见GitHub参考与改进说明，不复制其他组成果。
