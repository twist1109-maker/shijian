# v1.1.0 修复与验证

## 问题与修复
- 用户将密钥填在 config.example.json，旧版没有解释为何未读到。新增模型配置页、保存与测试接口；后端识别示例文件误填、Windows .txt 后缀、无效JSON与占位符。
- 支持 .env、DEEPSEEK_API_KEY、OPENAI_API_KEY、通用 MODEL_API_KEY；忽略空环境变量；显示真实生效来源和配置绝对路径。密钥不在API中回显。
- 成功动作后按钮未恢复：统一finally恢复按钮，包含连续导出。
- 切换页签或页面丢失未保存输入：正文、任务、资料和审核意见在当前登录会话中保留；不把密钥存入前端持久存储。
- 提交前需手动保存容易误认为按钮无效：提交按钮先保存修改，再提交审核；错误明确显示。
- 导出原先只在可编辑状态出现：新增GET任务export后端接口，审核通过后仍可导出，HTML转义文案。
- 服务重启导致任务永久运行中：初始化将中断执行记为失败，保留已有版本并允许重试。
- 配置JSON无效会使state接口失败，且后台异常处理再次读取同一错误文件：诊断不再抛出异常，失败记录可靠落库。
- 静态资源增加no-store，更新后可用Ctrl+F5刷新，页面显示版本1.1.0。

## 验证
运行 `python -m unittest discover -s tests -v`：21项配置与后端接口回归通过。
运行 `node tests/test_frontend.cjs`：13项真实前端事件处理器测试通过（DOM与HTTP为明确的测试替身）。
运行Python编译检查、JavaScript语法检查均通过。
覆盖模型配置、示例文件误填、.env、环境变量优先级、隐藏扩展名、JSON错误、密钥不回显、连接成功/401/超时、两类工具调用、保存/提交/退回/通过、版本与导出、失败重试和重启恢复。

这些结果不等于真实DeepSeek/OpenAI服务商验证。连接与生成测试使用测试替身，不使用用户密钥，也不访问服务商；完整浏览器端到端与Windows实际运行仍需在用户电脑确认。此前24项测试属于初版结果，不与本轮数字混计。
